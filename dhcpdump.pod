=head1 NAME

B<dhcpdump> - DHCP packet dumper

=head1 SYNOPSIS

B<dhcpdump> [B<-h> I<regular-expression>] [B<-H>] [B<-j> | B<-t>] [B<-Z> I<user>] B<-i> I<interface>

B<dhcpdump> [B<-h> I<regular-expression>] [B<-H>] [B<-j> | B<-t>] [B<-Z> I<user>] B<-r> I<pcapfile>

=head1 DESCRIPTION

This command listens on a network interface to display the dhcp-packets for
easier checking and debugging.

=head1 USAGE

S<dhcpdump -i eth0>

If you want to filter a specific Client Hardware Address (CHADDR), then
you can specify it as a regular expression:

S<dhcpdump -i eth0 -h ^00:c0:4f>

This will display only the packets with Client Hardware Addresses
which start with 00:c0:4f.

The expression is matched against the full 16 byte CHADDR field formatted
as colon separated hex pairs, so a 6 byte Ethernet address is followed by
ten C<:00> pairs; anchored expressions need to account for that (C<^00:c0:4f>
matches, C<4f:82:ac:7f$> does not).

Option B<-H> will additionally show full packet hex dump.

Option B<-j> prints every packet as one line of JSON instead, for scripts and
log pipelines; see L</JSON OUTPUT>.

Instead of getting live data from an interface, a pcap dump file can be
used:

S<dhcpdump -r pcapfile>

Opening an interface needs privileges, but decoding packets does not, and
those packets come from anyone able to reach the network. Option B<-Z> drops
to an unprivileged user once the capture handle is open, so the decoder never
runs as root:

S<dhcpdump -i eth0 -Z nobody>

The supplementary groups, the group id and the user id are all changed, and
the drop is verified to be irreversible before any packet is read. On Linux
every capability is cleared as well, so B<-Z> also gives up the
I<cap_net_raw> of a binary granted it with B<setcap>(8) and started by an
unprivileged user; B<-Z> then names that same user.

=head1 TUI (SESSION TRACKING)

Option B<-t> switches to an interactive full-screen view that groups packets
into sessions by client hardware address, and within each client into
transactions by transaction id (XID). Each transaction lists its messages
(for example DISCOVER, OFFER, REQUEST, ACK) and a derived, colour coded state:
I<wait> (a request is still awaiting its reply), I<offered>, I<complete>
(bound), I<NAK>, I<declined> (the client refused the address, e.g. found it
in use), or I<timeout> (a reply never arrived in time). Repeated
retransmissions are collapsed with a count, and an offer from a server the
client did not ultimately pick is shown in yellow.

With B<-i> the view updates live as packets arrive; with B<-r> the whole
capture is loaded first and then browsed. The B<-h> filter applies here too,
restricting which clients are tracked. Clients are shown in a stable
first-seen order so the list does not reshuffle as traffic arrives.

The view has two panes. In the client list on the left/top select a client,
then move into the detail pane to pick one of its packets, then open the full
decode of that packet - the same detail the line mode prints.

The following keys are available:

=over

=item B<q>, B<Ctrl-C> - quit (from any view)

=item B<h>, B<H>, B<?>, B<F1> - toggle a help dialog listing the keys for the current pane

=item B<v>, B<V> - toggle between side-by-side and top/bottom layouts

=item B<u> / B<a> - use UTF-8 box glyphs / plain ASCII

=item B<Ctrl-L> - redraw the screen

=item B<Ctrl-Z> - suspend; resume with the shell's job control (fg)

=back

In the client list:

=over

=item B<j> / B<k>, B<Down> / B<Up> - select a client

=item B<g> / B<G>, B<Home> / B<End>, B<PgUp> / B<PgDn> - jump / page

=item B<Right>, B<Enter> - move into the detail pane

=item B<Tab>, B<Shift-Tab> - move into the detail pane

=back

In the detail pane:

=over

=item B<j> / B<k>, B<Down> / B<Up>, B<PgUp> / B<PgDn> - select a packet

=item B<Left>, B<Esc>, B<Backspace> - back to the client list

=item B<Tab>, B<Shift-Tab> - back to the client list

=item B<Right>, B<Enter> - open the full decode of the selected packet

=back

In the packet decode:

=over

=item B<Left> / B<Right> - previous / next packet

=item B<Up> / B<Down>, B<PgUp> / B<PgDn> - scroll

=item B<< < >> / B<< > >> - pan horizontally when the decode is wider than the screen

=item B<Esc>, B<Backspace> - back to the detail pane

=back

At the option field, the first field is the value of the option,
the second one (between brackets) is the length of the option-datafield,

=head1 JSON OUTPUT

With B<-j> each DHCP packet is written as one JSON object on a line of its
own (JSON Lines), flushed as it is written, so the output can be piped into
tools such as B<jq>(1). For example, to print every NAK:

  dhcpdump -i eth0 -j | jq -c 'select(any(.options[]?; .code == 53 and .value == 6))'

Diagnostics stay on stderr, so stdout carries only JSON. With B<-H> the frame
is added to its packet's object as a B<frame_hex> field instead of being
printed, and every option and relay agent sub-option also carries its raw
bytes as B<hex> next to its decoded B<value> (an over-long value keeps its
extra bytes only there); unlike the text output, which dumps every captured frame, this only
covers the frames that are written as a packet object, so not ones that are
not DHCP, are filtered out by B<-h> or carry an empty payload. B<-j> cannot be
combined with B<-t>.

Each packet object has B<schema> (1, changed only for an incompatible
change), B<ts> (capture time in epoch seconds with a microsecond fraction),
B<time> (the same instant as local ISO 8601 time with UTC offset, or null if
it cannot be represented as a date), B<vlan> (only when tagged: a list of
objects with B<type> C or S and B<id>, outer tag first), B<src> and B<dst>
(objects with B<ip> and B<mac>) and B<len> (the payload length).

A payload shorter than the 236 byte BOOTP header only adds B<truncated>
(true). Otherwise these follow: B<op>, B<htype>, B<hlen>, B<hops>, B<secs> and
B<flags> as numbers; B<op_text> and B<htype_text> for known values; B<xid> as
8 hex digits; B<ciaddr>, B<yiaddr>, B<siaddr> and B<giaddr> as dotted quads;
B<chaddr> in colon hex, the first B<hlen> bytes of the field, or all 16 when
B<hlen> is 0 or larger than 16; B<sname> and B<file>, as
text when printable, as B<sname_hex> and B<file_hex> otherwise, and null when
they carry overloaded options; and B<options>. Plain BOOTP without the magic
cookie has B<vendor_hex> instead of B<options>.

B<options> lists the options in packet order, leaving out pad and end. Each
is an object with B<code>, B<name> and B<len>, plus its value, either as
B<value> or, for raw bytes, as B<hex>. A value that does not fit its option's
structure carries B<malformed> (the reason) and B<hex> instead. An option cut
off by the end of the packet has B<malformed> set to truncated and B<hex>
holding what is left of it, and no B<len> when even its length byte is
missing. Options taken from an overloaded field add B<source>, set to file or
sname. By option, B<value> is:

=over 4

=item a dotted quad string

1, 16, 28, 32, 50, 54, 118.

=item a list of dotted quad strings

3-11, 41, 42, 44, 45, 48, 49, 65, 68-76, 85, 92, 148, 150.

=item a number

13, 22, 23, 26, 37, 57, 145 (8 and 16 bit values); 24, 35, 38, 51, 58, 59,
91, 108, 153, 211 (durations in seconds); 152, 154, 155 (absolute times in
epoch seconds); 2 (time offset in seconds, negative west of UTC).

=item a number with a name

19, 20, 27, 29-31, 34, 36, 39, 46, 52, 53, 116: B<value> is the number and
B<text> its name, left out when the value has no name.

=item a list of numbers

25.

=item an object

78: B<mandatory> (the flag byte) and B<addrs> (a list of dotted quads);
81: B<flags>, B<rcode1>, B<rcode2> and B<name> (B<name_hex> when not
printable, left out when absent); 94: B<type>, B<major> and B<minor>.

=item a list of objects

21: B<addr> and B<mask>; 33: B<dest> and B<router>; 121, 249: B<dest> (in
address/prefix length form) and B<via>; 55: B<code> and B<name> of each
requested option; 93: B<value> and B<text> (when known) of each architecture;
82: one per sub-option with B<code>, B<name> (when known), B<len> and
B<value> or B<hex>, or B<malformed> when the sub-option does not fit (no
B<len> when only its code is left, B<hex> with what is left when it is too
large); 162 (encrypted DNS, RFC 9463): one per DNR instance with
B<priority>, B<adn> (the authentication domain name, dotted, without the
trailing dot and C<.> for the root; B<adn_hex> with its wire format when a label
is not printable or holds a dot) and, unless the instance is in ADN-only
mode, B<addrs> (a list of dotted quads) and B<svcparams>.

B<svcparams> lists the service parameters (RFC 9460) of the instance in
order, each an object with B<key> (the number), B<name> (when known) and its
value: for mandatory a list of key numbers, for alpn a list of strings (B<hex>
when an id is not printable), for port a number, for ipv4hint and ipv6hint a
list of address strings, for dohpath a string (B<hex> when not printable);
no-default-alpn and ohttp have no value, and ech and unknown keys give
B<hex>, left out when empty. 162 is malformed when an instance or a service
parameter does not fit, the name is not uncompressed DNS wire format ended
by the root label, an instance that is not ADN-only has no address or an
address length that is not a multiple of 4, the keys are not strictly
increasing, or a known key has a value of the wrong shape. An instance split
over several 162 options (RFC 3396) is not joined, so each part is decoded
on its own.

=back

63 is always given as B<hex>. All the other options have no structured type:
B<value> when every byte is printable ASCII, B<hex> otherwise, and neither
when empty.

Strings only ever hold printable ASCII and everything else is given as hex,
so the output is valid JSON whatever a packet contains.

=head1 RETURN VALUES

0 on a normal run, 1 on any error: bad usage, capture setup failure, or a
live capture that dies mid-run.

=head1 NOTES

Privileged access is often needed for accessing the interface. Use B<-Z> to
give those privileges up again as soon as the interface is open.

Only Ethernet captures are supported. Notably, the Linux B<any>
pseudo-interface does not capture in Ethernet framing and is rejected;
capture on a specific interface instead.

=head1 BUGS

Not all the parameter options are printed verbose, because of lack of
documentation. Not all the options are tested, because of lack of
clients/servers with these options. If you have a dump of one of
them, please send them to me and I'll incorporate them.
